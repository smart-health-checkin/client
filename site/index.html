@smart-health-checkin/client

The JavaScript client

The provider side of SMART Health Check-in as one await: ask the patient's health app for what the visit needs, and get a verified response back in your own page. CBOR, COSE and HPKE stay inside.

How a check-in runs

Install

From git, pinning a branch or a commit — there is no npm registry involved:

npm install github:smart-health-checkin/client            # or bun add, pnpm add
npm install github:smart-health-checkin/client#<commit>

Or as a hosted module, with no build step:

import { requestCheckin } from "";

Pinned copies outlive a rebuild: ·

The call

const response = await requestCheckin({
  purpose: "Before your visit with Dr. Reyes",
  items: [{
    id: "allergies",
    title: "Allergies and intolerances",
    content: {
      kind: "selection.fhir",
      profiles: ["http://hl7.org/fhir/us/core/StructureDefinition/us-core-allergyintolerance"],
    },
    accept: ["application/fhir+json"],
  }],
});

response.artifacts;       // [{ mediaType: "application/fhir+json", value: {…} }]
response.requestStatus;   // [{ item: "allergies", status: "fulfilled" }]

A response that reaches you has been decrypted, signature-checked, and cross-checked against the request. What happens next — prefill, write FHIR, take payment — is your code. An optional fhir module maps a response to a transaction Bundle if you want that done for you. Getting started →
