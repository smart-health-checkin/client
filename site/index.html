smart-health-checkin

checkin-provider-kit

Embed a SMART Health Check-in flow in any provider web surface, receive the patient's response right there, submit it to your FHIR server, and return the patient to the rest of check-in. The Digital Credentials API plumbing stays inside the kit.

Open the demo GitHub Draft spec

How a check-in runs

One config object describes the whole flow

import { runCheckin } from "@smart-health-checkin/provider-kit";

const outcome = await runCheckin({
  request:  { scenario: "phq2-dayof" },
  context:  { patient: "Patient/123" },
  submit:   { fhirBase: "https://fhir.example.org/r4" },
  complete: { returnUrl: "https://portal.example.org/checkin/next" },
});

Status: working draft. The core flow — request construction, SessionTranscript, HPKE, COSE verification, FHIR submission — is implemented and byte-verified against real Chrome/Android captures from the spec prototype's conformance fixtures. The README is the API contract; the demo runs end-to-end today (use mock=1 if you don't have a wallet-equipped phone handy).
